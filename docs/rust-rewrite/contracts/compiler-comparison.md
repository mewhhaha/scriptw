# Co-measured compiler comparison

[Compiler benchmarks](../../../.github/workflows/compiler-benchmarks.yaml) is a
manually dispatched GitHub Actions workflow. Run it on `main` with `publish=true`
to measure and commit the README images, JSON report, Markdown table and compressed
raw evidence directly to `main`:

```sh
gh workflow run compiler-benchmarks.yaml --ref main -f publish=true
```

`publish=false` retains an Actions artifact without committing it. The measurement
job has read-only repository access. Only the separate publishing job can write.
Runs serialize, publication requires `main` still to equal the measured source,
and a normal non-force push closes the final race. A moved branch fails publication;
dispatch again against its new source. GitHub-token pushes do not start ordinary
push CI, so publication performs its own evidence, graph, tooling and status checks.

All three engines use the complete, unchanged 17-case
[execution corpus](../../../crates/scriptw-cli/tests/fixtures/v8_execution_hotpaths/manifest.json).
The two rounds reverse case order and rotate runtime order. Each case/runtime gets
ten warmups followed by seven measured invocations in a process dedicated to that
case. Medians pool fourteen measured observations. Builds and measurements use
a confirmed 4-GiB systemd process-tree scope, zero swap, grouped OOM and one CPU.

Scriptw uses the existing `runtime_baseline` example. V8 uses the existing
`node-runtime.cjs` fixture with a fresh context each time. Scriptc 0.4.5 and its
matching WASI runtime pack compile JavaScript with `SCRIPTC_TARGET=wasm32-wasi`
and Zig 0.16.0. Only the harness adapter
`function print(value) { console.log(String(value)); }` is prefixed to each input.
The benchmark-only `wasi_baseline` Rust example loads those command modules using
Wasmtime 47.0.0 and the same product Fast/copying-GC configuration. The extra WASI
dependency is a CLI development dependency; it does not alter the product compiler.

Execution timing excludes source/Wasm compilation and instance/context setup;
it includes program execution and output/completion handling. Each invocation
uses a fresh Store or V8 context. WASI `_start` includes its C/runtime startup;
Scriptw likewise includes its JavaScript realm/bootstrap execution. No cost is
subtracted. The endpoint RSS is sampled while the Store/context is alive and
includes the full process, compiler/runtime and retained warmup effects. It is
neither live JavaScript heap nor peak RSS. No forced GC is used. Shared-host
measurements make no statistical-significance or conformance claim.

Frontend placement differs: Scriptw and V8 compile JavaScript in the measured
host process; Scriptc's JavaScript compiler runs separately. Scriptc's RSS thus
includes Wasm native compilation, but excludes its JavaScript frontend process.
The graph compares complete host-process footprints under these recorded paths.

A smoke program must build and run successfully before per-case failures become
data. Every original case keeps its own image. A Scriptc compile failure, runtime
failure or changed checksum has a visible label and no performance bar. Inputs
with lone UTF-16 surrogates keep their original contents and expected output.
Failures and timeouts retain commands, exit statuses, stdout and stderr. A failed
Scriptw or V8 reference run aborts publication. Incomplete evidence remains an
Actions artifact and cannot replace the graph.

The README shows one image per benchmark, with thick vertical bars for execution
time and post-execution RSS. Each panel starts at zero and scales to that case;
values and units make comparisons explicit. Source, date and timing boundaries
appear once above the grid, with complete observations in the evidence.

Verify or regenerate the images offline:

```sh
python3 -B scripts/benchmark-compilers.py check docs/rust-rewrite/compiler-comparison.json
python3 -B scripts/render-execution-performance.py --check
python3 -B scripts/render-execution-performance.py
python3 -B scripts/render-execution-performance.py --case retained-objects.js --preview /tmp/retained-objects.png
```

The workflow pins matplotlib 3.11.2 for byte-stable SVG verification. Historical
two-runtime checkpoints keep their own evidence and can still be rendered with
an explicit `--report` path. The current pinned Test262 results are independent
and are never regenerated by this benchmark workflow.
